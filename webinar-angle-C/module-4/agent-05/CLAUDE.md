# Project notes — sim-real runtime

> Raw braindump from the engineer who set up this workspace. Has not been refactored into a polished doc. Read it once, then lean on AGENTS.md (which is the *structured* layer) for the team conventions.

This workspace is the data + code half of a sim-real correlation effort. There is a Kinematic Single-Track (KS) model that predicts lateral vehicle dynamics from real CAN-bus inputs captured by openpilot, on three platforms. Ford CSVs contain measured yaw-rate and lateral-G truth channels; Tesla CSVs don't.

## How to run

System `python3` already has `pandas`, `numpy`, `scipy`, `matplotlib` pre-installed. Run scripts as `python3 ...`.

```bash
python3 code/run_ks_synthetic.py            # synthetic open-loop demo (no rlog needed)
python3 code/generate_simdata_ford.py       # rlog → KS → CSVs (only Fords have truth)
python3 code/plot_simdata_ford.py           # PNGs alongside CSVs
```

`code/_README.md` has a longer description if you want it.

## What the model does

It's a kinematic single-track (KS) model. Real-data runs are in "speed-known lateral-only" mode — `clamp_v_to_measured=True` and `clamp_delta_to_measured=True`, so the integrator clamps `v` and `δ` to measured values at every step and only the lateral states (yaw, yaw-rate, a_y, x, y) are predicted. That's the operating contract for this workspace. AGENTS.md restates this where it matters.

## CSV columns (Ford only — Tesla doesn't have the truth channels)

The per-segment CSVs at 50 Hz include columns like:

- `t_s`, `delta_wheel_deg`, `delta_road_rad`, `v_mps`, `a_long_mps2`
- `a_lat_meas_mps2`, `yaw_rate_meas_rads`   ← measured truth (Ford only)
- `x_m`, `y_m`, `psi_rad`, `v_state_mps`, `delta_state_rad`
- `yaw_rate_pred_rads`, `a_y_pred_mps2`     ← KS prediction
- `yaw_rate_resid_rads`, `a_y_resid_mps2`   ← (pred − meas)

If a column you need isn't here, `head` one of the CSVs.
